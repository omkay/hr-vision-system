# دليل الاختبار اليدوي — ميزات تكامل الرؤية

خطوات عملية لاختبار التسجيل (enrollment)، تسجيل الحضور اليومي (checkin)، وتتبع النشاط حسب المناطق يدوياً. يفترض هذا الدليل أن حزمة Docker تعمل بالفعل (`docker compose up -d` من مجلد المشروع الرئيسي)، وأن لديك `curl` و`python3` في الطرفية.

استبدل `admin`/`password123` ببيانات الدخول الفعلية إذا كانت مختلفة.

## ٠. تسجيل الدخول والحصول على token

```bash
TOKEN=$(curl -s -X POST http://localhost:8080/api/login \
  -H "Accept: application/json" -H "Content-Type: application/json" \
  -d '{"user_name":"admin","password":"password123"}' \
  | python3 -c "import sys,json;print(json.load(sys.stdin)['token'])")
echo $TOKEN
```

كل طلب أدناه يحتاج `-H "Authorization: Bearer $TOKEN"` و`-H "Accept: application/json"`. الـ token تنتهي صلاحيته بعد ٦٠ دقيقة من عدم النشاط — أعد تشغيل هذا الأمر إذا ظهرت رسالة انتهاء الجلسة.

## ١. التسجيل بصور متعددة (Multi-photo enrollment)

**إنشاء موظف تجريبي** (أو استخدم موظفاً موجوداً بمعرف `id`):

```bash
curl -s -X POST http://localhost:8080/api/employees/add \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN" \
  -F "name=Test Employee" -F "Administration=IT" -F "job_num=9999" \
  -F "position=Engineer" -F "start_date=2026-08-11" -F "start_time=09:00" -F "end_time=17:00"
```

لاحظ قيمة `id` المُرجعة (سنسميها `EMPLOYEE_ID`).

**رفع عدة صور وجه/جسم:**

```bash
curl -s -X POST http://localhost:8080/api/employees/EMPLOYEE_ID/photos \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN" \
  -F "face_images[]=@/path/to/face1.jpg" \
  -F "face_images[]=@/path/to/face2.jpg" \
  -F "body_images[]=@/path/to/body1.jpg"
```

هذا يُطلق عملية التسجيل تلقائياً في الخلفية — انتظر ٥-١٠ ثوانٍ ثم تحقق من نجاحها:

```bash
docker compose exec vision-service python3 -c "
import numpy as np
z = np.load('/app/gallery/gallery.npz', allow_pickle=True)
print('enrolled names:', z['names'].tolist())
"
docker compose exec vision-service ls /app/gallery/9999/face/   # يجب أن تظهر صورتا الوجه
docker compose exec vision-service ls /app/gallery/9999/body/   # يجب أن تظهر صورة الجسم
```

(`9999` هو `job_num` — وهو مفتاح الهوية في خدمة الرؤية، وليس `id` في Hr_SmartPay.)

**اختبار أن الحذف يزيل الصورة فعلياً:**

```bash
curl -s -X DELETE http://localhost:8080/api/employees/EMPLOYEE_ID/photos/PHOTO_ID \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN"
# انتظر ٥ ثوانٍ ثم أعد التحقق:
docker compose exec vision-service ls /app/gallery/9999/face/   # يجب أن تظهر صورة واحدة فقط الآن
```

إذا فشل أي شيء، راجع `docker compose logs hr-queue` — التسجيل يعمل كمهمة خلفية في الطابور (queue)، وليس مباشرة ضمن الطلب.

## ٢. تسجيل الحضور اليومي (Attendance checkin)

يستخدم أي صورة قمت بتسجيلها أعلاه.

```bash
curl -s -X POST http://localhost:8080/api/checkin \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN" \
  -F "photo=@/path/to/face1.jpg"
```

المتوقع: `201` مع سجل حضور إذا تطابقت الصورة مع موظف مسجل، أو `422` إذا لم يتم التعرف عليها.

**جرّب مرة أخرى فوراً** — يجب أن تحصل الآن على `409` "تم تسجيل الحضور مسبقاً":

```bash
curl -s -X POST http://localhost:8080/api/checkin \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN" \
  -F "photo=@/path/to/face1.jpg"
```

**عرض سجل الحضور:**

```bash
curl -s http://localhost:8080/api/checkins -H "Accept: application/json" -H "Authorization: Bearer $TOKEN"
# فلاتر اختيارية: ?employee_id=EMPLOYEE_ID أو ?date=2026-08-11
```

إذا توقف طلب تسجيل الحضور لحوالي ٣٠ ثانية ثم فشل، تأكد من وجود `PHP_CLI_SERVER_WORKERS=4` في إعدادات خدمة `hr-app` بملف `docker-compose.yml`، وأنك أعدت البناء بعد أي تعديل عليه (`docker compose up -d hr-app`).

## ٣. تتبع النشاط حسب المناطق (Zone-based activity tracking)

هذا الجزء الأبطأ في الاختبار — معالجة الفيديو الحقيقية تستغرق عدة دقائق على المعالج (CPU).

**إنشاء منطقة** (إن لم تكن موجودة):

```bash
curl -s -X POST http://localhost:8080/api/zone/add \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"name":"Main Warehouse","zone_type":"common_area"}'
```

**رفع فيديو كاميرا.** مهم: يجب أن يكون الملف بصيغة MP4/MOV مُرمّزة بشكل صحيح (تحقق باستخدام `file yourvideo.mp4` — يجب أن تظهر النتيجة "ISO Media" أو ما شابه، وليس "data"). بعض تسجيلات أجهزة NVR الخام قد تفشل في فحص Laravel لنوع الملف.

```bash
curl -s -X POST http://localhost:8080/api/camera/add \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN" \
  -F "name=Entrance Camera" -F "zone_id=ZONE_ID" -F "video=@/path/to/video.mp4"
```

لاحظ قيمة `id` الخاصة بالكاميرا (`CAMERA_ID`).

**بدء المعالجة:**

```bash
curl -s -X POST http://localhost:8080/api/camera/CAMERA_ID/process \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN"
```

يعيد الطلب استجابة فورية مع `vision_job_id` وحالة `running` — التحليل الفعلي للفيديو يجري في الخلفية.

**متابعة التقدم مباشرة من خدمة الرؤية** (اختياري، للمراقبة فقط):

```bash
curl -s http://localhost:8000/events/VISION_JOB_ID | python3 -m json.tool
```

قيمة `progress` ترتفع من ٠ إلى ١.٠. قد يستغرق هذا عدة دقائق حسب طول الفيديو — مهمة الاستعلام الدوري في Hr_SmartPay تتحقق كل ١٠-١٢٠ ثانية تقريباً (فترات تصاعدية)، لذا قد تتأخر النتائج قليلاً عن انتهاء المعالجة الفعلي في خدمة الرؤية.

**التحقق من حالة المهمة في قاعدة بيانات Hr_SmartPay:**

```bash
docker compose exec mysql mysql -uroot -proot hr_smartpay \
  -e "SELECT id, status, error_message FROM vision_jobs;"
```

بمجرد أن تصبح الحالة `done`، اجلب النتائج:

```bash
curl -s http://localhost:8080/api/camera/CAMERA_ID/events \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN"
# فلاتر اختيارية: ?employee_id=...، ?event_type=presence|working|phone_use|interaction، ?date=...
```

كل حدث يعرض `employee_name`/`job_num` إذا تعرفت خدمة الرؤية على شخص مسجل مسبقاً، أو `null` إذا رصدت شخصاً غير معروف.

**تشغيل دفعي** (عدة كاميرات في مهمة واحدة):

```bash
curl -s -X POST http://localhost:8080/api/cameras/process-batch \
  -H "Accept: application/json" -H "Authorization: Bearer $TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"camera_ids": [1, 2]}'
```

## استكشاف الأخطاء وإصلاحها

- **`docker compose ps` لا تُظهر أي شيء يعمل**: نفّذ `docker compose up -d --build` من مجلد المشروع الرئيسي (إعادة البناء تلتقط أي تعديلات على الكود منذ آخر بناء للصور).
- **فشل تسجيل الدخول**: تحقق من وجود الحساب في جدول `users` — `docker compose exec mysql mysql -uroot -proot hr_smartpay -e "SELECT * FROM users;"`.
- **أي شيء متعلق بالطابور (queue) يبدو متوقفاً**: `docker compose logs hr-queue` يُظهر كل محاولة تنفيذ مهمة مع حالتها (RUNNING/FAIL/DONE) والوقت المستغرق — أسرع طريقة لمعرفة ما يحدث فعلياً.
- **أخطاء خدمة الرؤية**: `docker compose logs vision-service` — أخطاء Python تظهر هنا مباشرة.
